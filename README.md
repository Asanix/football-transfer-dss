# Football Transfer DSS: Moneyball 2.0 for a top club

Система поддержки принятия решений (DSS) для спортивного директора: аудит состава → поиск
недооценённых игроков под нашу тактическую модель → оптимальный план трансферного окна под
бюджет → меморандум, который пишет LLM.

**Ключевой вопрос.** Каких игроков клубу купить, продать и отдать в аренду в окно 2022/23, чтобы
максимально усилить старт под стиль 4-3-3 (владение и высокий прессинг) при ограниченном
трансферном и зарплатном бюджете? И находит ли наша система кандидатов лучше, чем простая
сортировка по рейтингу?

Клуб по умолчанию: **Real Madrid CF**. Меняется одним параметром.

Сценарии из задания: №1 (аудит клуба), №3 (Moneyball) и №5 (DSS-продукт). Уровень 3, Decision Intelligence.

## Быстрый старт (для того, кто запускает)

Нужен Python **3.10–3.13**.

### 1. Среда
Windows (PowerShell, из папки проекта):
```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```
macOS / Linux: `bash setup.sh`

### 2. Данные
Датасет: [FIFA 23 Complete Player Dataset](https://www.kaggle.com/datasets/stefanoleone992/fifa-23-complete-player-dataset).
Нужен один файл, `male_players.csv` (несколько ГБ, версии FIFA 15–23).

- **Вариант А, автоматически.** Нужен Kaggle API token. Скачайте `kaggle.json` в Kaggle →
  Settings → API → Create New Token и положите его в `C:\Users\<you>\.kaggle\kaggle.json`
  (или `~/.kaggle/kaggle.json`). Пайплайн скачает файл сам.
- **Вариант Б, вручную.** Скачайте `male_players.csv` со страницы датасета и положите его в
  `data/raw/male_players.csv`.

### 3. Запуск
Windows:
```powershell
.\run.ps1                          # пайплайн + дашборд (Real Madrid)
.\run.ps1 -Club "Real Sociedad"    # другой клуб
.\run.ps1 -NoApp                   # только пайплайн
```
Если PowerShell не даёт запускать скрипты, выполните команды вручную:
```powershell
$env:PYTHONPATH="src"; .\.venv\Scripts\python.exe -m football_dss.pipeline --club "Real Madrid CF"
.\.venv\Scripts\python.exe -m streamlit run app.py
```
macOS / Linux: `bash run.sh` (другой клуб: `CLUB="Real Sociedad" bash run.sh`).

Первый запуск занимает 5–15 минут: читается CSV на несколько ГБ и обучаются модели. Повторные
запуски быстрее, потому что используется `data/processed/players.parquet`.

## Структура
```
src/football_dss/
  config.py      пути, клуб, тактическая модель (веса атрибутов по позициям), бюджетные допущения
  data.py        загрузка, чанковое чтение CSV, последний апдейт каждого сезона, качество данных
  features.py    группы позиций, role_fit под нашу тактику, style_bonus, контракт, таргеты t+1
  models.py      fair value, прогноз развития, риск спада; time split + baseline
  style.py       кластеризация стилей (KMeans + silhouette) и поиск дешёвых «двойников»
  squad.py       аудит состава против 10 сильнейших клубов, кандидаты на продажу и аренду
  scouting.py    Moneyball-скор, шорт-листы, «скрытые таланты», бэктест против простых рейтингов
  optimizer.py   ILP-оптимизатор окна (scipy milp / HiGHS), сценарии бюджета 100/80/60/40%
  llm_report.py  когнитивный слой: меморандум из посчитанных фактов
  pipeline.py    весь процесс от начала до конца
app.py           Streamlit-дашборд
tests/make_synthetic.py   генератор фейковых данных для smoke-теста
```

## Методология

| Этап | Что делаем | Почему так |
|---|---|---|
| Данные | FIFA 17–23, по одной строке на игрока и сезон (последний апдейт) | несколько сезонов позволяют валидировать модели во времени |
| Тактическая модель | `role_fit` = взвешенные атрибуты, которые важны **для нашего** стиля в каждой группе позиций | `overall` в FIFA оценивает игрока «в целом», а не под конкретный стиль |
| `style_bonus` | `role_fit − overall` | рынок оценивает `overall`, поэтому разница между ними = потенциальная недооценка |
| Fair value | HistGradientBoosting по log(value); для текущего сезона прогноз out-of-fold | без OOF собственная цена игрока утекает в его «справедливую» цену |
| Развитие и риск | Δoverall и P(спад ≥ 2) в следующем сезоне | перепродажа и риск неудачного трансфера |
| Стиль | KMeans внутри позиции по *форме* профиля (атрибуты минус среднее игрока) | 70-рейтинговый и 85-рейтинговый игрок с одинаковым профилем получаются «двойниками» |
| Решение | ILP: максимизировать прирост старта при ограничениях на трансферы, зарплаты, число покупок и глубину состава | рейтинг сам по себе не учитывает бюджет и состав одновременно |

**Альтернативы, которые мы рассматривали:** линейная регрессия (оставлена как baseline),
жадный выбор вместо ILP (ILP учитывает все ограничения сразу), кластеризация без нормировки
профиля (тогда кластеры просто повторяют уровень игрока).

## Проверка качества (заполняется из `reports/results.md` после запуска)
- **Time split.** Модели обучаются на FIFA ≤ 22, тест на FIFA 23 (для развития: пары ≤ 21→22, тест 22→23).
- **Baseline.** Каждую модель сравниваем с простым подходом: медиана по (overall, возраст),
  средняя Δ по возрасту, логистическая регрессия по (возраст, overall).
- **Бэктест DSS.** Списки на FIFA 22, построенные только по информации на тот момент,
  сравниваются с тем, что произошло в FIFA 23. Сравниваем три стратегии: «сортировка по
  overall», «overall / цена» и наш Moneyball-скор.
- **Валидация похожести.** Находит ли профиль игрока из прошлого сезона его же самого в
  текущем (top-5 hit rate против случайного угадывания).
- **Чувствительность.** Как меняется план при бюджете 80/60/40%.

## Ловушки и ограничения (обязательный раздел)
1. **Data leakage.** Убрали `release_clause_eur` (EA считает его из value) и `wage_eur`
   (назначается вместе с value). В моделях развития признаки берутся только из сезона t.
   Fair value считается out-of-fold.
2. **Разные позиции.** Все скоры, z-нормировки, кластеры и бенчмарки считаются внутри группы
   позиций. Вратарей и нападающих одним критерием не сравниваем.
3. **Игровые рейтинги ≠ реальный рынок.** `value_eur` в FIFA — это формула EA, а не реальная
   трансферная цена. Комиссия ×1.2 и скидка при продаже ×0.85 — наши допущения
   (`config.py`). Вывод «недооценён» относится к модели EA, на реальном рынке это нужно
   подтверждать скаутингом.
4. **Разные чемпионаты.** Рейтинг 75 в лиге второго уровня и в АПЛ означает разное. Частично это
   учитывает `league_level`, но смещение остаётся.
5. **Устаревшие данные.** Снимок соответствует сезону 2022/23. Составы и цены сейчас другие.
   Проект — это демонстрация метода, а не актуальные рекомендации.
6. **Корреляция ≠ причинность.** Важность признаков в модели развития показывает связь, а не
   причину роста.
7. **Неопределённость.** Риск спада — это вероятность, а не гарантия. В оптимизаторе он
   учитывается как штраф.
